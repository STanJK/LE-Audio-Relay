# V0.20 — First Stabilized Tray Form

**Released:** 2026-09-27  
**Status:** frozen milestone

V0.20 is the first version of LE Audio Router that is intentionally frozen as a Windows Tray application architecture rather than as an experimental console relay.

## What is stabilized

- A persistent Windows Tray / Supervisor process owns product lifetime.
- Application lifetime itself expresses routing intent.
- Recovery is automatic and is not exposed as a user preference.
- One disposable child process represents one Audio Route generation.
- The worker boundary is explicitly a user-mode fault and diagnostic boundary.
- Worker startup uses a typed local named-pipe handshake.
- Worker liveness is monitored through heartbeat messages.
- Manual **Restart audio route** replaces the current generation.
- Render category can be selected from GameEffects, GameMedia, Media, and Default/unset.
- GameEffects is the default category.
- Legacy V0.1 remains isolated under `Legacy/V0.1/` and is excluded from the current build graph.
- The current architecture is documented by `MODULE_MAP.md`, `docs/ARCHITECTURE.md`, ADR 0001, and the Round4 VF-KB.

## What is intentionally not in V0.20

V0.20 does not yet contain the rewritten audio routing backend.

The current worker proves only:

```text
Tray lifetime
→ Supervisor
→ disposable worker generation
→ handshake / heartbeat
→ replacement / recovery
```

The next development stage will introduce the new `Routing/` implementation inside the worker without changing the V0.20 shell ownership model.

Clock synchronization, endpoint/power lifecycle observation, and long-run audio telemetry remain later modules.

## Architecture significance

V0.20 is the boundary between:

```text
V0.1
experimental Process Loopback relay
application lifetime == route lifetime
```

and:

```text
V0.20
stabilized Tray product shell
application lifetime > route-generation lifetime
```

This version is therefore the canonical baseline for subsequent Round4 routing work.
