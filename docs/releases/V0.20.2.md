# V0.20.2 — Event-Driven Endpoint Lifecycle

**Released:** 2026-09-27  
**Status:** frozen milestone  
**Development baseline:** `f31850f198476414088000f5e7188354e17e4812`

## Why this version is preserved

V0.20.2 is the first frozen Round4 build where disconnect/reconnect behavior is modeled as Windows endpoint lifecycle rather than as repeated backend failure.

It preserves the transition from:

```text
V0.20.1:
disconnect
→ worker fails
→ wait fixed 3 seconds
→ spawn another worker
→ repeat
```

to:

```text
V0.20.2:
disconnect
→ endpoint topology changes
→ supervisor re-enumerates
→ target absent
→ zero workers
→ wait

reconnect
→ endpoint topology changes
→ supervisor re-enumerates
→ target active
→ one fresh worker generation
```

## Architecture frozen by this release

### Product lifetime

The Tray/Supervisor process is the durable product lifetime.

### Route lifetime

One worker PID represents one disposable RouteSession generation.

### Endpoint lifecycle

`Lifecycle/AudioEndpointObserver` subscribes to NAudio/Core Audio endpoint notifications with synchronization-context marshalling disabled.

Notification callbacks do one thing:

```text
Wake()
return
```

They do not enumerate endpoints, create/dispose WASAPI objects, or start/stop workers.

`Lifecycle/AudioEndpointProbe` then re-enumerates current active render endpoints and the default multimedia render endpoint.

The architecture rule is:

```text
notification != state
notification = something changed
enumeration  = what is true now
```

### State reconciliation

```text
TargetEndpointAvailability.Absent
    => WaitingForEndpoint
    => zero workers

TargetEndpointAvailability.Ambiguous
OR unsafe/default render topology
    => TopologyBlocked
    => zero workers

Available + safe topology
    => one healthy route worker should exist

worker/route failure while topology remains eligible
    => RecoveringFault
    => bounded retry 1s / 2s / 5s / 10s / 30s
```

## Manual validation before release

This release candidate passed:

1. connected startup → Running;
2. disconnect → worker exits, Tray survives;
3. disconnected waiting → no repeated worker process churn;
4. reconnect → one new generation → Running;
5. mode switch → one generation replacement;
6. invalid default output → TopologyBlocked, no worker;
7. restoring sacrificial default output → automatic return to Running.

## What remains outside V0.20.2

- Windows suspend/resume observation;
- single-ear/topology-specific Buds behavior beyond Windows endpoint observations;
- active ring drift/clock synchronization;
- timing recentering/sample-slip/PLL/ASRC;
- richer always-on diagnostics and persistent logs.

## Historical significance

```text
V0.20   = first stabilized Tray shape
V0.20.1 = first real audio route + fixed retry
V0.20.2 = first real audio route + event-driven endpoint lifecycle
```

V0.20.2 is the baseline for the next Lifecycle step: Windows suspend/resume.
