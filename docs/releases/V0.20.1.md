# V0.20.1 — First Real Audio-Routing Tray Build

**Released:** 2026-09-27  
**Status:** frozen historical milestone  
**Implementation baseline:** 2146e3e7a58fbebaba530034d67b434e007a8b08

## Why this version is preserved

V0.20 froze the first stable Tray/supervisor form before audio was reintroduced.

V0.20.1 is the next important boundary: it is the first frozen Round4 build where the Tray architecture, disposable worker generation, and rewritten real audio route all operate together.

It is intentionally preserved before the endpoint lifecycle model changed from fixed retry to event-driven reconciliation.

## Included architecture

```text
Tray / Supervisor process
    ↓
Backend generation N
    ↓
RouteSession
    ↓
Process Loopback
    ↓
PcmRelayBoundary
    ↓
Persistent Buds render
```

The route uses:

- 48 kHz Float32 stereo;
- destination-first startup;
- Process Loopback excluding the worker process tree;
- one SPSC ring;
- real-zero keepalive;
- startup cushion gating;
- separate audio/silent drop telemetry.

## Recovery behavior

V0.20.1 uses a fixed recovery delay:

```text
route or worker failure
    ↓
Supervisor fault/recovery state
    ↓
wait 3 seconds
    ↓
start next generation
```

The supervisor does not yet distinguish endpoint physically absent from endpoint present but route initialization/runtime failed.

As a result, disconnecting Galaxy Buds3 Pro can produce repeated short-lived worker generations at approximately three-second intervals.

This behavior is retained because V0.20.1 is an evidence-bearing milestone. Later versions replace it rather than rewriting its history.

## VF-KB snapshot

The release includes the Round4 knowledge hierarchy that existed at this milestone:

```text
round4-shell
└── worker-generation
    ├── fixed-retry-recovery
    └── route-session
        └── pcm-relay-boundary
```

The fixed retry policy is explicitly represented by VF/fixed-retry-recovery.vf.md.

## Successor direction

The immediate successor work introduces a Lifecycle layer where:

```text
notification = wake-up
enumeration  = truth

target absent
    => zero workers
```

That successor behavior is deliberately not backported into V0.20.1.
