# V0.21 Daily Test Candidate 1 — Fact Page

## why

The project has reached the point where short functional checks are no longer the main evidence gap. Endpoint disconnect/reconnect has already been exercised, but the new power lifecycle, lifecycle journal, provisional positive-drift guard, and their interactions need sustained ordinary use.

Testing a moving branch would make later observations ambiguous. This candidate therefore freezes the exact runtime baseline before the long-run validation round begins.

## what

V0.21 Daily Test Candidate 1 freezes runtime baseline `326fa42cf2a6069c97ab11c9a60e635b4481c1c0`.

It contains the current daily-use foundation:

- Tray/Supervisor product lifetime;
- one disposable worker generation;
- real Process Loopback → Buds RouteSession;
- event-driven endpoint lifecycle reconciliation;
- WM_POWERBROADCAST-based suspend/resume facts;
- PowerRevision invalidation of every pre-resume worker generation;
- low-volume lifecycle-only persistent journal;
- provisional positive-drift guard regulating post-render residual fill around the 10 ms target cushion.

The candidate is explicitly **not yet a stable/public release**. Multi-hour and multi-day behavior remains under test.

## outcome

This branch is an evidence boundary. It should not be rewritten to hide failures discovered during dogfooding.

If the complete daily-use validation round is satisfactory, its design can become the basis for formal V0.21 and the first public-facing documentation baseline.

If defects appear, those observations belong to this candidate. Fixes occur on the development branch and, when necessary, a later daily-test candidate is frozen for another complete validation round.
