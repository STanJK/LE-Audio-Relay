# V0.20.2 — Release Fact Page

## why

V0.20.1 proved that the new Tray/Supervisor, child-process generation model, and handwritten audio route could recover automatically, but it also exposed a semantic flaw: physical endpoint absence was handled as a generic route failure and therefore created repeated worker processes.

V0.20.2 is preserved because it is the first release where that distinction is explicit in architecture and validated in real use.

## what

V0.20.2 keeps the real Process Loopback → PcmRelayBoundary → persistent Buds render route from V0.20.1. It adds a Lifecycle layer in the Tray/Supervisor process:

- Core Audio endpoint notifications only wake supervision.
- Fresh endpoint enumeration is authoritative.
- Absent Buds enter WaitingForEndpoint with zero worker processes.
- Ambiguous/unsafe topology enters TopologyBlocked with zero workers.
- Reconnect creates one new worker generation only after the target becomes active.
- Real route failures while topology remains eligible use bounded 1/2/5/10/30-second recovery backoff.

The release record also preserves the manual validation performed before freezing this version.

## outcome

V0.20.2 becomes the baseline for subsequent lifecycle work. Disconnect/reconnect is no longer implemented as process churn, and the next major lifecycle concern—Windows suspend/resume—can feed the same reconciliation model instead of adding another independent recovery mechanism.
