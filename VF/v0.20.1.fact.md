# V0.20.1 Fixed Retry Recovery — Fact Page

## why

V0.20.1 is the first frozen Round4 build that combines the Tray/supervisor shell with the rewritten real audio route. At this point automatic route replacement already existed, but Windows endpoint lifecycle observation did not. The fixed delay was therefore a pragmatic recovery mechanism rather than an endpoint-aware state model.

## what

BackendSupervisor uses one fixed three-second recovery interval after a worker generation completes unexpectedly or after generation startup fails. It then returns to reconciliation and creates another generation because the product-level intent remains "application alive means routing should run."

There is no authoritative endpoint probe between the failure and the next worker attempt. Consequently, a disconnected Buds endpoint follows the same recovery path as a transient WASAPI or worker failure.

## outcome

Transient failures can self-recover without user intervention. Persistent endpoint absence can also create repeated worker generations roughly every three seconds. V0.20.1 freezes this behavior as historical evidence so the later event-driven Lifecycle design can be compared against a concrete predecessor rather than replacing its record.
